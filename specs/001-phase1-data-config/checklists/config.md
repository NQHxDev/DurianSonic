## Requirement Clarity

- [x] CHK007 Are strict inequality versus inclusive inequality boundaries (`>` vs `>=`, `<` vs `<=`) unambiguously specified for every numeric parameter in `DspConfig` (`sample_rate`, `window_sec`, `pre_onset_sec`, `min_interval_sec`, `threshold_ratio`, `n_fft`, `hop_length`, `n_mels`, `fmin`, `fmax`, `top_db`)? [Clarity, Spec §FR-003, Data-Model §2.2]
- [x] CHK008 Is the Nyquist frequency constraint for `fmax` mathematically unambiguous regarding floating-point comparison (`fmax <= (sample_rate as f32) / 2.0` vs strict `<`) and lower-bound ordering (`0.0 <= fmin < fmax`)? [Clarity, Spec §FR-003, Data-Model §2.2]
- [x] CHK009 Is the power-of-two constraint for `n_fft` explicitly defined as both strictly positive (`n_fft > 0`) and an exact power of two (`n_fft.is_power_of_two()`)? [Clarity, Spec §FR-003, Data-Model §2.2]
- [x] CHK010 Is the onset window temporal relationship (`0.0 <= pre_onset_sec < window_sec`) clearly specified so that pre-onset padding cannot equal or exceed the total impulse window duration? [Clarity, Spec §FR-003, Data-Model §2.2]
- [x] CHK011 Is the floating-point sum tolerance for dataset split ratios (`train_ratio + val_ratio + test_ratio`) explicitly quantified as an absolute difference `< 0.0001` (`1e-4`), along with individual positivity bounds (`> 0.0` and `< 1.0`)? [Clarity, Spec §FR-003, Data-Model §2.3]
- [x] CHK012 Are the valid domain bounds for `learning_rate` (`0.0 < lr < 1.0`), `weight_decay` (`>= 0.0`), `label_smoothing` (`0.0 <= ls < 1.0`), and `dropout` (`0.0 <= dropout < 1.0`) defined without ambiguity between `f32` and `f64` representations? [Clarity, Spec §FR-003, Data-Model §2.4–2.5]
- [x] CHK013 Is the allowed enumeration of `ModelConfig::activation` values (`["relu", "sigmoid", "tanh", "leaky_relu"]`) and its case-sensitivity rule explicitly specified? [Clarity, Data-Model §2.5]
